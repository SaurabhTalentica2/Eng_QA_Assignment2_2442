VAmPI API Security Assessment

Target: http://localhost:5000

Summary: Critical: 2 High: 3 Medium: 1

Executive Summary

A comprehensive API security assessment of the VAmPI application was conducted, evaluating 10 discovered endpoints against the OWASP API Security Top 10 framework. The evaluation revealed a severely compromised security posture, identifying 6 confirmed vulnerabilities—comprising two Critical, three High, and one Medium severity finding. The most severe threats involve a Critical Broken Object Level Authorization (BOLA) flaw on the password modification endpoint (CVSS 9.3) and a Critical Mass Assignment vulnerability during user registration (CVSS 9.1), which together enable unauthorized password overrides and arbitrary privilege escalation. Furthermore, High-severity access control and authentication weaknesses allow unauthenticated access to private user records, sensitive data leaks via a debug endpoint, and JWT token manipulation. The login interface also lacks basic rate-limiting controls, leaving the application highly susceptible to automated brute-force attacks. Collectively, these vulnerabilities expose the business to severe risks of total account takeover, administrative privilege compromise, and extensive unauthorized data exposure, requiring immediate prioritized remediation.

Vulnerability Findings (6)

VULN_MASS · Mass Assignment allows privilege escalation at registration Critical · CVSS 9.1

OWASPAPI6:2019 Mass Assignment
EndpointPOST /users/v1/register
CVSS VectorCVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N
DescriptionRegistration binds client-supplied fields directly to the user model, so an attacker can set admin=true and self-provision administrator privileges.
Evidence (PoC)
POST /users/v1/register with admin=true -> 200. GET /users/v1/admintest_d32c5e9f shows admin flag set: {"admin": true, "email": "qa_e67734b4@example.com", "password": "Password123!", "username": "admintest_d32c5e9f"}
RemediationBind only an explicit allow-list of fields (username, password, email). Never accept privilege/role fields from client input.

VULN_BOLA · Broken Object Level Authorization on user modification Critical · CVSS 9.3

OWASPAPI1:2019 Broken Object Level Authorization
EndpointPUT /users/v1/{username}/password
CVSS VectorCVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H
DescriptionAn authenticated user can modify another user's object (password) because the server does not verify that the token owner matches the targeted username.
Evidence (PoC)
Attacker 'attacker_6820374d' token used to PUT /users/v1/victim_278de321/password -> 204; subsequent login as victim with attacker-set password succeeded.
RemediationEnforce object-level authorization: derive the target user from the authenticated token, not from the path parameter, or verify ownership before mutating.

VULN_JWT · Weak JWT authentication configuration High · CVSS 7.3

OWASPAPI2:2019 Broken User Authentication
EndpointPOST /users/v1/login
CVSS VectorCVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N
DescriptionThe JWT issued at login has weaknesses that undermine authentication: HS256 (symmetric) signing - vulnerable if secret is weak/guessable.
Evidence (PoC)
JWT header={"alg": "HS256", "typ": "JWT"} payload={"exp": 1788160196, "iat": 1788160136, "sub": "qa_c2961b83"}
RemediationUse a strong, secret-managed signing key (or asymmetric RS256), enforce short-lived tokens with an 'exp' claim, and reject 'none'.

VULN_BFLA · Unauthenticated access to user records High · CVSS 7.5

OWASPAPI5:2019 Broken Function Level Authorization
EndpointGET /users/v1/{username}
CVSS VectorCVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N
DescriptionThe user-detail endpoint returns any user's record to an unauthenticated caller, enabling account enumeration and unauthorized information disclosure.
Evidence (PoC)
GET /users/v1/admin sent with NO Authorization header -> 200, returned: {"username": "admin", "email": "admin@mail.com"}
RemediationRequire authentication and enforce function-level authorization so users can only read records they are permitted to access.

VULN_RATE · Missing rate limiting on authentication Medium · CVSS 5.3

OWASPAPI4:2019 Lack of Resources & Rate Limiting
EndpointPOST /users/v1/login
CVSS VectorCVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N
DescriptionThe login endpoint accepts unlimited authentication attempts with no throttling or account lockout, enabling brute-force and credential-stuffing attacks.
Evidence (PoC)
12 consecutive failed logins all succeeded without a 429/lockout. HTTP codes observed: [200, 200, 200, 200, 200, 200, 200, 200, 200, 200, 200, 200]
RemediationApply per-IP and per-account rate limiting, exponential backoff, and account lockout after repeated failures.
